# X 推文串草稿：10 月 Agent Passport v0.1（2026-09-19）

---

（1/7）
今天把 AI Agent 职业规划路线上的 10 月主线跑完了一大块：Agent Passport v0.1。

核心问题：一个 AI Agent 怎么证明"我是谁"？把 EOA、EIP-712、EIP-1271、ERC-8004、ENS 这五个概念串成了一条完整的身份闭环，全部有可运行代码验证。开源在 agent-lab。

（2/7）
起点很简单：一对私钥/公钥就是最基础的链上身份（EOA）。私钥签名不暴露秘密，任何人拿"地址+内容+签名"就能验证是不是这个身份签的——而且内容改一个字，验证立刻失败。

这是后面所有机制的地基。

（3/7）
签纯文本不够安全——用户根本看不懂自己在签什么，容易被钓鱼。EIP-712 把签名内容变成有字段名、有类型的结构化数据，比如"授权调用 read_file，限额10次，10月底过期"，每个字段独立防篡改。

Agent 之间的授权声明，必须靠这个。

（4/7）
如果账户不是私钥控制，而是一个智能合约（比如多签钱包）呢？合约没有私钥。EIP-1271 的解法是：验证方不再自己用密码学算法判断，而是直接问合约"你认不认这个签名"，规则完全由合约自定义。

我写了个 2-of-2 多签模拟场景，三种情况全部符合预期。

（5/7）
ERC-8004 是专门给 AI Agent 设计的身份标准（不是给人用的），今年8月刚发布，已经部署到主网和20多条链。核心是把每个 Agent 变成一个 NFT：tokenId 是身份编号，指向一份类似 A2A Agent Card 的注册文件。

关键点：它能保证身份记录没被篡改，但不能保证 Agent 声称的能力是真的——这是 Reputation/Validation 要解决的问题。

（6/7）
最后用 ENS 把一串 0x... 的地址变成人类记得住的名字，直接查了真实以太坊主网数据（vitalik.eth 正向反向解析都测了）。

把这五个概念整合成 Agent Passport v0.1：签发一份身份声明、验证归属+签名+有效期，还专门测了篡改、过期、伪造身份三种攻击场景，全部被正确拦截。
