# 从零跑通 Agent Loop、Tool Calling、MCP、A2A：2026 年 9 月学习笔记

这是 [AI Agent 职业规划手册](../../README.md) 2026 年 9 月的产出：agent-lab 仓库下四个最小 Demo。目标不是"学会某个框架"，而是能独立解释 Agent 是怎么"思考、调用工具、协作"的，并且每个概念都有一份能跑起来的代码作为证据。

## 1. Agent Loop：一切的起点

Agent 和普通的一次性问答的区别，就在于有没有这个循环：

```
思考 -> 判断要不要调用工具 -> 执行工具 -> 把结果喂回去 -> 再思考 -> ... -> 给出最终答案
```

`src/01-basic` 里用不到 100 行代码实现了这个循环：LLM 收到问题后，自己判断要不要调用 `read_file` 工具；如果要调用，代码执行读取、把结果塞回消息列表，再把新的消息列表发给模型；如果不需要调用，直接返回最终内容。核心是一个 `while(true)` 循环，退出条件是"这次响应里没有工具调用了"。

这里最容易被忽略的一点：**Agent 的"记忆"就是这个不断增长的 `messages` 数组**。没有额外的存储、没有复杂的向量库，最简单的 Agent 记忆就是把每一轮的对话和工具结果都追加进上下文,再整体发给模型。

## 2. Tool Calling：从"一个工具"到"多个工具怎么选"

`src/02-tool-calling` 把工具从 1 个扩展到 3 个：`list_files`（列目录）、`read_file`（读文件）、`search_notes`（关键词搜索）。这一步真正测试的是模型的"工具选择"和"多步骤规划"能力，而不是工具调用机制本身（机制在 01 已经验证过了）。

实测下来，模型面对"这个目录下有哪些笔记文件？找到讲 MCP 的那篇，总结一下"这种问题，会自己规划出两步：先 `list_files` 拿到文件名列表，再针对性地 `read_file` 读取匹配的那篇。这个规划过程完全是模型自主完成的，代码里没有写任何"先做什么再做什么"的逻辑。

## 3. MCP：把工具变成"可以被发现"的东西

前两个 Demo 里，工具就是同一个进程里写好的函数,模型知道有哪些工具，是因为我们把 schema 硬编码塞进了 `tools` 参数。MCP（Model Context Protocol）解决的是另一个问题：**工具可以运行在完全独立的进程/服务里，Client 通过标准协议动态发现它们，而不是硬编码**。

`src/03-mcp` 分成两个文件：`server.ts` 用官方 SDK 的 `McpServer` 起了一个独立进程，暴露 3 个工具；`index.ts` 把这个 server 当子进程启动，先用 `tools/list` 问它"你有哪些工具"，再把返回的 schema 转换成 LLM 能理解的格式，最后模型决定调用哪个工具时，走 `tools/call` 真正跨进程执行。

这里的关键收获是：**MCP 的价值不在"能调用工具"，而在"工具描述和调用方式被标准化了"**。理论上换一个完全不同的 MCP Server（比如别人写的天气服务），Client 端代码完全不用改，因为发现和调用的协议是一样的。

## 4. A2A：Agent 之间怎么"认识"对方

MCP 解决的是"Agent 怎么用工具"，A2A（Agent-to-Agent）解决的是"Agent 怎么找到并使用另一个 Agent"。两者的相似之处是都有"发现"这一步；不同的是 A2A 发现的是一整个 Agent 的能力描述（Agent Card），而不是某个具体工具的参数 schema。

`src/04-a2a` 里，Server 端定义了一个 `AgentCard`（名字、描述、技能列表），跑起来后会在 `/.well-known/agent-card.json` 这个固定路径上暴露它。Client 端先访问这个地址拿到 Agent Card，再用标准的 JSON-RPC 协议 `sendMessage`。整个过程验证了 A2A 最基础的闭环：**发现 -> 连接 -> 发消息 -> 拿结果**，还没涉及更复杂的 Task 状态机和流式 Artifact（那是后面阶段的内容）。

## 一条隐藏的共同逻辑

四个 Demo 表面上是四个不同的技术点,但拼起来看会发现一条主线:

- Agent Loop 关心的是"一个 Agent 内部怎么循环"
- Tool Calling 关心的是"这个 Agent 怎么在多个能力里做选择"
- MCP 关心的是"工具能力怎么脱离具体 Agent，被标准化地发现和调用"
- A2A 关心的是"整个 Agent 的能力怎么被别的 Agent 发现和调用"

从"内部循环"到"工具标准化"到"Agent 标准化"，粒度在不断放大。这也是为什么手册把这四个放在同一个月：它们不是孤立的知识点，而是同一套"发现 -> 授权/连接 -> 调用 -> 结果"模式在不同层级上的重复应用——这正是手册第二十节说的"第一性原则"。
